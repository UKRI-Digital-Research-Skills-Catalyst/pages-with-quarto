Build a website with Quarto and GitHub Pages

Published

8 October, 2026

Introduction

Why a Quarto website?

  • Typically people build websites in drag-and-drop website builders or by writing HTML by hand. Each has a learning curve and often a monthly cost.

  • Content and layout get tangled together, so changing the look of a site means editing every page.

  • It can be hard to see what changed, who changed it, or to go back to an earlier version.

  • Moving a site between tools or hosting providers is a lot of manual labour ….. and error prone

What is Quarto?

  • An open-source scientific and technical publishing system that allows you to create documents, presentations, books and websites from plain text files.

  • You write in Markdown, a lightweight markup language for creating formatted text using a plain-text editor. It was designed by John Gruber in 2004. Quarto turns it into web pages.

  • Quarto can also run code (R, Python, Julia and Observable) and put the results in your pages. We do not need that today, but your site can grow to include it.

  • This website is a Quarto website.

What are GitHub and GitHub Pages?

  • GitHub is a website for storing and sharing files in a repository. It keeps a complete history of every change.

  • GitHub Pages is a free service that turns the files in a repository into a website with an address like https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/

  • GitHub Actions is GitHub’s built-in automation. We will use it to run Quarto for us, so that nothing needs to be installed on your computer.

How the pieces fit together

Every time you save a change to your repository, the following happens automatically:

  1. You edit a file in your web browser and save (“commit”) the change.

  2. GitHub Actions starts a small computer in the cloud, installs Quarto and turns your .qmd files into web pages.

  3. GitHub Pages publishes the web pages at your website address.

It takes a minute or two from saving to seeing the change on your website.

Exercises

Scenario

You have been asked to create a small website for yourself, your group or your project. It should have a home page, an about page, a navbar to move between them and a look of its own.

By the end of this workshop you will have a live website at an address you can share.

Throughout, we use the repository name my-first-quarto-site. You are welcome to choose your own name. Wherever you see YOUR-USERNAME in the instructions, replace it with your own GitHub username.

Part 1: Set up a GitHub account

If you already have a GitHub account, sign in at https://github.com/login and skip to Part 2.

🎬 Open a new browser tab and go to https://github.com/signup

You can sign up in one of three ways. Choose the one you decided on in the pre-course instructions and follow the matching steps.

Option 1: Continue with Google

🎬 Click Continue with Google

🎬 Choose your Google account and allow GitHub to use it to sign in

🎬 If GitHub asks you to choose a username, see Choosing a username below

Option 2: Use your Microsoft email address

GitHub does not currently have a “Continue with Microsoft” button1. You can still sign up with a Microsoft email address (an Outlook or Hotmail address, or a Microsoft work or school address) by using the email form.

🎬 Type your Microsoft email address into the Email box and click Continue

🎬 Create a password. Use a long one that you do not use anywhere else

🎬 Choose a username, see Choosing a username below

🎬 Complete the puzzle if GitHub shows you one

🎬 GitHub emails you a code. Open your Microsoft inbox, find the email from GitHub and type the code into the box on the sign-up page

Option 3: Use any other email address

The steps are exactly the same as Option 2, but with an email address from any other provider, such as your university, your employer or a personal address.

Choosing a username

Your username is public and it becomes part of your website address, for example https://YOUR-USERNAME.github.io/. Choose something you are happy to share with colleagues and collaborators.

  • Letters, numbers and single hyphens work best
  • Short is better
  • You can change your username later but your website address will change with it

Finishing up

🎬 If GitHub asks you to personalise your experience, you can skip it

🎬 If asked to choose a plan, choose the free plan (Continue for free)

🎬 Check you can see the GitHub home page with your username or avatar in the top right corner

TipVerify your email and keep your account safe

You need a verified email address to create repositories. If GitHub has asked you for a code, make sure you have entered it. GitHub also recommends turning on two-factor authentication (2FA) or a passkey, which you can do after the course in your account settings.

ImportantChallenge

Sign out and then sign back in using the same route you used to sign up (Google, or your email and password). The menu for signing out is under your avatar in the top right corner. Making sure you can get back in now saves a lot of worry later.

Part 2: Create a repository and publish it

Create a repository

A repository (or “repo”) is a project folder stored on GitHub. Your website will live in one.

🎬 Click the + in the top right corner of GitHub | New repository

🎬 Fill in the form:

  • Repository name: my-first-quarto-site2

  • Description: optional

  • Choose Public3

  • Tick Add a README file

  • Leave everything else as it is

🎬 Click Create repository

You now have a repository containing one file, README.md.

Turn on GitHub Pages

🎬 Click the Settings tab at the top of your repository4

🎬 In the left menu, click Pages

🎬 Under Build and deployment, find Source and choose GitHub Actions from the drop-down list

This tells GitHub that you will provide instructions (a “workflow”) for building your website. We will add the workflow shortly. The setting saves itself, so there is nothing else to click.

Add the Quarto configuration file

Every Quarto website has a configuration file called _quarto.yml. It describes the website. Note the underscore at the start of the name.

🎬 Click the Code tab to go back to your files

🎬 Click Add file | Create new file

🎬 In the name box, type _quarto.yml

🎬 Paste this into the big text box:

project:
  type: website

website:
  title: "My first Quarto site"

🎬 Click Commit changes… and then, in the box that appears, leave Commit directly to the main branch selected and click Commit changes5

🚨 Indentation matters in YAML. Make sure title is indented two spaces under website, and type is indented two spaces under project.

Add the home page

🎬 Click Add file | Create new file

🎬 In the name box, type index.qmd

🎬 Paste this into the big text box:

---
title: "Hello, world!"
---

This is my first Quarto website.

🎬 Click Commit changes… and then Commit changes

index.qmd is the file that becomes your home page. The part between the three dashes is the YAML header which describes the page. The rest is the content.

Add the publishing workflow

The last file tells GitHub to build and publish the website every time you save a change. It has to be in a particular folder.

🎬 Click Add file | Create new file

🎬 In the name box, type .github/workflows/publish.yml. Notice that each time you type a /, GitHub turns what you typed into a folder

🎬 Paste this into the big text box:

name: Publish Quarto site to GitHub Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Check out the repository
        uses: actions/checkout@v4

      - name: Set up Quarto
        uses: quarto-dev/quarto-actions/setup@v2

      - name: Render the Quarto project
        run: quarto render

      - name: Configure GitHub Pages
        uses: actions/configure-pages@v5

      - name: Upload the site
        uses: actions/upload-pages-artifact@v3
        with:
          path: _site

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4

You do not need to understand every line today. In short:

  • on says when to run: every time you commit to the main branch
  • build installs Quarto and turns your .qmd files into a website (quarto render)
  • deploy publishes that website with GitHub Pages

🎬 Click Commit changes… and then Commit changes

🚨 The most common problem is indentation. If your workflow fails, compare it carefully with the one above.

Watch your website being built

🎬 Click the Actions tab

You will see a workflow run called “Publish Quarto site to GitHub Pages”. A yellow circle means it is running, a green tick means it worked and a red cross means something went wrong.

🎬 Wait for the green tick. This usually takes a minute or two

🎬 Click Settings | Pages. At the top you will see the address of your website. It looks like https://YOUR-USERNAME.github.io/my-first-quarto-site/

🎬 Click Visit site, and bookmark your website

TipTroubleshooting

If the workflow shows a red cross, click it, then click the failed step to read the error. Check that:

  • In Settings | Pages, the Source is GitHub Actions
  • The files are called exactly _quarto.yml and index.qmd, including the underscore and the lower case letters
  • The workflow is at exactly .github/workflows/publish.yml
  • The indentation matches the examples

You can re-run a failed workflow by clicking Re-run all jobs.

If the workflow has a green tick but the website says “404”, wait a minute and refresh the page.

ImportantChallenge

Share the address of your website with the person next to you or in the chat. Can you find out what the address of their website is?

Part 3: Create website content with Quarto

Edit a page

🎬 In the Code tab, click index.qmd

🎬 Click the pencil icon (Edit this file) at the top right of the file

🎬 Change the sentence below the header to something about you, your group or your project

🎬 Click Commit changes… and then Commit changes

🎬 Click the Actions tab, wait for the green tick and then refresh your website

This is the rhythm of working with a Quarto website on GitHub: edit, commit, wait, refresh. It is slower than previewing on your own computer, so make a few changes before each commit.

TipKeep two windows open

Keep your website in one tab and your repository in another. After each commit, swap to the website tab and refresh it once the Actions tab shows a green tick.

Edit the YAML header

The YAML header sits between the two lines of three dashes at the top of every .qmd file. It holds information about the page such as its title.

🎬 Edit index.qmd and change the YAML header to:

---
title: "Hello, I'm Your Name"
subtitle: "Welcome to my first Quarto website"
author: "Your Name"
date: last-modified
---

🎬 Replace “Your Name” with your own name

🎬 Commit the changes and refresh your website

🚨 YAML is fussy. Keep the quote marks, keep the colon followed by a space and do not remove the dashes. If your website stops building, look at the header first.

Headings and text

Quarto pages are written in Markdown. Here are the most useful bits of syntax.

Markdown Syntax Output
# Header 1 A first level heading (the biggest)
## Header 2 A second level heading
### Header 3 A third level heading
*italics* italics
**bold** bold
***bold italics*** bold italics
~~strikethrough~~ strikethrough
`verbatim code` verbatim code

For lists, start each line with a dash for a bulleted list or with 1., 2. and so on for a numbered list. Leave a blank line before the list.

🎬 Delete the sentence in index.qmd and replace it with the text below, making the content your own:

This is my website, built with Quarto and GitHub Pages. You will find:

  • Information about me
  • Links to my work
  • Things I am interested in

🎬 Make one word italic

🎬 Add a second level heading called ## What I do and a short paragraph below it

🎬 Commit the changes and refresh your website

Links and images

Markdown Syntax Output
[Quarto](https://quarto.org) Quarto
![Caption](photo.jpg) An image with a caption
![Caption](photo.jpg){width="300"} An image 300 pixels wide

The text in square brackets before an image is its caption and its description for people using screen readers. Please always write one.

🎬 Add a sentence to index.qmd with a link to a website you like

🎬 Add a picture to your repository. Choose a small picture on your computer (a JPG or PNG under about 1 MB works best). In your repository, click Add file | Upload files, drag the picture in, then click Commit changes

🎬 Edit index.qmd and add the picture, using the exact name of your file:

![A short description of the picture](photo.jpg){width="300"}

🎬 Commit the changes and refresh your website

🚨 File names on GitHub Pages are case sensitive. Photo.JPG and photo.jpg are different files, and the website will show a broken picture if the name in index.qmd does not match the file exactly.

Add a second page

🎬 Click Add file | Create new file and call it about.qmd

🎬 Add this text and make it about you:

---
title: "About"
---

I work on ...

## Contact

You can find me at ...

🎬 Commit the changes

🎬 Edit index.qmd and add a link to your new page:

Read more [about me](about.qmd).

Notice that you link to the .qmd file. Quarto changes the link to the web page when it builds the website.

🎬 Commit the changes and refresh your website

Callouts

Callouts draw attention to some text. They are made with a “div”, which is a group of lines between a line starting with three colons and a line with only three colons.

🎬 Add a callout to index.qmd:

::: {.callout-tip title="Did you know?"}
Quarto turns plain text into web pages.
:::

🎬 Commit the changes and refresh your website

There are five types of callout: note, tip, important, warning and caution. Change callout-tip to callout-note and see what happens.

Part 4: Create a navbar

So far, the only way to get from one page to another is by following links that you typed. A navbar is a menu bar across the top of every page. It is described in _quarto.yml.

Add a navbar

🎬 Click _quarto.yml and then the pencil icon (Edit this file)

🎬 Replace the contents with:

project:
  type: website

website:
  title: "My first Quarto site"
  navbar:
    left:
      - text: "Home"
        href: index.qmd
      - text: "About"
        href: about.qmd

🎬 Commit the changes, wait for the green tick and refresh your website

You should see a bar across the top of your website with the title of your site and two links. Let us look at how the file is organised:

  • navbar is inside website, so it is indented two spaces
  • left is inside navbar, so it is indented four spaces. It is the list of links on the left of the bar
  • Each link starts with a dash - and has a text (what visitors see) and an href (the page it goes to)

🚨 Use spaces, never tabs, and keep the indentation exactly as shown.

Add more to the navbar

🎬 Edit _quarto.yml and add a search box and a link to your repository on the right side of the bar. Replace YOUR-USERNAME with your username:

project:
  type: website

website:
  title: "My first Quarto site"
  navbar:
    search: true
    left:
      - text: "Home"
        href: index.qmd
      - text: "About"
        href: about.qmd
    right:
      - icon: github
        href: https://github.com/YOUR-USERNAME/my-first-quarto-site
        aria-label: GitHub repository

🎬 Commit the changes and refresh your website

ImportantChallenge

Add your projects.qmd page to the navbar. If you did not make it, make it now.

ImportantChallenge

Navbar links can also be grouped into a drop-down menu using menu. Can you find out how by looking at the Quarto navigation guide and make a drop-down menu called “More” that holds your About and Projects pages?

Part 5: Change the look of your site with styles.css

Quarto websites are made of HTML, which says what is on the page, and CSS (Cascading Style Sheets), which says how it looks. Quarto writes the HTML for you, and you can add your own CSS in a file called styles.css to change the colours, fonts and layout.

Create the stylesheet

🎬 Click Add file | Create new file and call it styles.css

🎬 Paste this into the big text box:

/* css styles */

h1, h2, h3 {
  color: #58579B; /* blue */
}

🎬 Click Commit changes… and then Commit changes

Nothing will change on your website yet, because Quarto does not know about your stylesheet.

Tell Quarto to use your stylesheet

🎬 Edit _quarto.yml and add this to the end, at the very left edge (it is not inside website):

format:
  html:
    css: styles.css

🎬 Commit the changes, wait for the green tick and refresh your website. Your headings should now be blue

A CSS rule has three parts:

  • A selector says what to change. Here h1, h2, h3 means “the first, second and third level headings”
  • A property says what aspect to change. Here color is the text colour
  • A value says what to change it to. Here #58579B is a colour written as a hexadecimal code. You can also use colour names such as tomato or teal

🎬 Change the colour to one you like. Search the web for “colour picker” to find codes for other colours

Style the navbar

🎬 Edit styles.css and add these rules to the end:

/* Style the navbar */
.navbar {
  background-color: #2E2D62 !important; /* navy */
}

.navbar .navbar-brand,
.navbar .navbar-title,
.navbar .nav-link {
  color: #FFFFFF !important; /* white */
}

.navbar .nav-link:hover {
  color: #FA6862 !important; /* pink */
}

🎬 Commit the changes and refresh your website

The !important tells the browser that your rule wins over Quarto’s own styling. It is a heavy hammer, so use it only when a change does not seem to work.

TipFind out what to change

Not sure what to call the thing you want to change? In your browser, right-click the part of your website and choose Inspect. The panel that opens shows the HTML for that spot, including the name of its class (the bit that starts with a dot in your CSS).

Change the font

🎬 Edit styles.css and add this to the very top of the file, above everything else:

@import url('https://fonts.googleapis.com/css2?family=DM+Sans:wght@400;700&display=swap');

body {
  font-family: 'DM Sans', sans-serif;
}

🎬 Commit the changes and refresh your website

🚨 An @import line must come before all of the other rules. If your font does not change, check it is at the top of the file.

Make your own box

You can also make your own styles and then use them on any part of a page. Earlier you made a callout, which is a div with a style. You can make your own.

🎬 Add this to the end of styles.css:

/* My own style: a highlighted box */
.highlight-box {
  background-color: #E0F1FA; /* light blue */
  border-left: 6px solid #29A69D; /* teal */
  padding: 1rem;
  margin: 1rem 0;
}

🎬 Edit index.qmd and add this to the page:

::: {.highlight-box}
This text is in a box styled by **my** CSS.
:::

🎬 Commit the changes and refresh your website

ImportantChallenge

Choose a palette of three colours for your website and use it for the headings, the navbar and the highlighted box. Can you also change the colours of the callout-tip callout you made earlier? Use the Inspect trick to find the names you need.

TipPrefer a ready-made look?

Quarto comes with a collection of ready-made themes. Add a line to _quarto.yml and your own styles.css still works on top of it:

format:
  html:
    theme: cosmo
    css: styles.css

You can see the others in the Quarto themes guide.

Summary

  • Quarto is a publishing system that turns plain text files into websites, documents and more.

  • GitHub stores your files with a full history of changes, and GitHub Pages publishes your website for free from a repository.

  • You can sign up to GitHub with a Google account, a Microsoft email address or any other email address.

  • A GitHub Actions workflow in .github/workflows runs Quarto for you each time you commit, so you do not need to install anything.

  • _quarto.yml describes the whole website and .qmd files are the pages. The YAML header at the top of each page gives its title and other details.

  • Markdown is used to make headings, lists, links and images. “Divs” group content together to make callouts or to apply your own styling.

  • The navbar is built in _quarto.yml with a list of links.

  • styles.css changes the look of the website with rules made of a selector, a property and a value.

Where next?

  • Quarto’s website guide shows how to add blogs, listings and more

  • The Markdown basics page has more syntax like tables and equations

  • GitHub Pages documentation explains how to use your own domain name

  • Set up two-factor authentication or a passkey for your GitHub account

  • Quarto can also run R or Python code and put the results in your pages. The Reproducible reports with Quarto workshop shows you how

Good luck on your future Quarto projects!
